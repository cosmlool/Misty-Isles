# Административные команды

Админ-команды по умолчанию отключены. Сервер разрешает их только персонажам, чьи точные player ID перечислены в серверной переменной окружения `MISTY_ADMIN_PLAYER_IDS`.

## Настройка

Перед запуском сервера задайте переменную в окружении процесса сервера:

```powershell
$env:MISTY_ADMIN_PLAYER_IDS = "acct_ваш_player_id,guest_доверенный_player_id"
npm run start
```

Несколько ID разделяются запятыми; пробелы вокруг ID удаляются. Сравнение точное и чувствительно к регистру. Пустая или отсутствующая переменная означает, что админ-команды недоступны всем.

Используйте только доверенные ID. Не задавайте эту переменную в клиентском Vite env, не включайте её в публичные файлы, репозиторий, логи или клиентские сборки. Переменная должна быть доступна только серверному процессу. Локальный launcher `tools/Start-Game.ps1` намеренно не задаёт `MISTY_ADMIN_PLAYER_IDS`, поэтому админ-команды в его обычном запуске выключены.

## Проверка безопасности

- Админ-сообщение проходит через общий authenticated-message wrapper: проверяется действующая серверная сессия, player ID сессии и принадлежность текущему клиенту.
- После этого сервер сверяет собственный `this.playerId` с allowlist. Переданный в payload ID или флаг роли не используется для назначения прав.
- Новый guest/account player ID создаётся сервером; привязка существующего гостевого ID при регистрации требует действующий guest recovery proof.
- Скрытие админ-кнопки в клиенте не является защитой; авторизация всегда выполняется на сервере.
- Не публикуйте тестовый сервер с админским allowlist без отдельной проверки конфигурации, доступа к окружению и всех admin-only операций.

## Доступные действия

Текущий обработчик поддерживает: `gold`, `crystals`, `gems`, `xp`, `level`, `heal`, `stats`, `materials`, `profession`, `resetDaily`, `resetCharacter`. Это мощные тестовые инструменты, изменяющие данные персонажа; используйте их только на тестовых данных.

Тесты `server/test/adminAuthorization.test.ts` проверяют разбор allowlist, пустую конфигурацию и точное совпадение ID. Они не заменяют отдельный end-to-end тест авторизации admin-сообщений в запущенном сервере.
