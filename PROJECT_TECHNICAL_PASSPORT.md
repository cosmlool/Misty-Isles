## 3. Локальная установка и проверки

Использовать Node.js 22 (как в CI). Для client/server применять `npm ci` в соответствующей папке.

Полная последовательность из корня:

```bash
node tools/qa-audit.mjs

cd client
npm ci
npm run verify:project

cd ../server
npm ci
npm test
npm run build

cd ../e2e
npm install
npm test
```

Playwright требует установленный Google Chrome и свободные порты 5173/2567. Для браузера с UI: `npm run test:headed`; для отчёта: `npm run report`.

### Единая команда VERIFY_PROJECT.bat

Теперь `VERIFY_PROJECT.bat` вызывает кроссплатформенный `tools/verify-all.mjs` и выполняет полный набор проверок:

1. Проверка файлов проекта, JSON и структуры через `tools/qa-audit.mjs`.
2. Установка отсутствующих зависимостей client/server/e2e (через `npm ci`, если есть lockfile; иначе `npm install`). Уже установленные `node_modules` повторно не устанавливаются.
3. Клиентские проверки, ассеты и production build через `npm run verify:project`.
4. Полный серверный набор через `npm test`.
5. Сборка сервера через `npm run build`.
6. Установка/проверка Chrome для Playwright.
7. Полные браузерные сценарии через `e2e/npm test`.

Скрипт останавливается на первой ошибке, печатает этап и команду, завершает работу ненулевым кодом. Требуется Node.js 22, как в CI. Для E2E пока нет зафиксированного `e2e/package-lock.json`, поэтому первая установка использует `npm install`; после появления локального lockfile последующие установки используют `npm ci`.

Отдельные команды:
- Client: `npm run build` — TypeScript + Vite; `npm run verify:project` — project checks + asset audit + build.
- Server: `npm test` — последовательный запуск тестов; `npm run build` — TypeScript build.
- E2E: `npm test` — Playwright browser suite.

## 4. GitHub Actions Quality Gate

Workflow `.github/workflows/quality.yml` содержит четыре задачи:

1. **Data, docs and project structure** — `node tools/qa-audit.mjs`.
2. **Client TypeScript and Vite build** — `npm ci`, затем `npm run verify:project`.
3. **Server TypeScript build** — `npm ci`, затем `npm test` и `npm run build`.
4. **Playwright browser smoke tests** — установка client/server/e2e dependencies, Chrome и `e2e/npm test`; диагностические артефакты сохраняются даже при ошибке.

CI — окончательная проверка изменения. Пустой список commit statuses или состояние pending не являются успехом. Проверять нужно последний HEAD PR, не старый SHA.

## 5. Сохранения и изоляция тестов

- Сервер по умолчанию использует `server/data`.
- `MISTY_DATA_DIR` задаёт отдельный абсолютный каталог; относительный путь сервер отклоняет.
- Runtime-тесты должны создавать временный каталог, копировать туда только нужные статические каталоги и удалять временную папку в `finally`.
- E2E использует синтетические аккаунты и временные сохранения; настоящая папка `server/data` не должна использоваться.
- Не запускать тесты против живого сервера или реальных аккаунтов.
- Перед изменением формата сохранений нужны анализ совместимости, миграционный тест, резервная копия/восстановление и crash/replay-тест.

## 6. Порядок дальнейшей разработки

1. Разрешить актуальный HEAD PR и проверить CI именно этого SHA.
2. Прочитать паспорт и audit/checkpoint-документы; сверить их с кодом.
3. Для бага сначала получить воспроизводящий тест/сценарий, затем исправлять подтверждённую причину.
4. Не менять игровую механику в рамках инфраструктурной правки.
5. Выполнить релевантные тесты, затем полный локальный verify насколько доступна среда.
6. Зафиксировать commit и дождаться всех CI jobs. При сбое записать job, тест, сообщение, SHA и ссылку на run.
7. Сохранить checkpoint: что изменено, что проверено, что не проверено, текущие HEAD/PR/CI и следующий шаг.
8. Не удалять временные/неиспользуемые файлы до проверки импортов, ссылок, build, тестов и миграций.

## 7. Обнаруженные пробелы

- Нет корневого npm-пакета; полный набор проверок теперь запускается через `VERIFY_PROJECT.bat` / `tools/verify-all.mjs`.
- E2E-проект пока не имеет зафиксированного `e2e/package-lock.json`; CI и локальная первая установка используют `npm install`, что оставляет дерево E2E-зависимостей менее воспроизводимым, чем client/server.
- Для E2E CI использует `npm install`; отдельный обязательный e2e lockfile не включён в текущий QA required-file list. Вопрос фиксации дерева зависимостей нужно решить отдельно.
- `PROJECT_AUDIT_STATUS.md` содержит исторические checkpoint-записи и ранние состояния веток; перед использованием сверять их с текущим PR и SHA.

Упал logout runtime test: тестовый запрос создания персонажа не передавал обязательное поле `gender`. Тестовый сценарий исправлен в следующем коммите; новый CI ещё должен подтвердить исправление.
