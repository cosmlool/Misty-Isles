# Карта совместимости legacy-ресурсов Misty-Isles

Срез подготовлен 2026-11-26 для ветки `docs/equipment-crafting-design-2026-11-25`. Документ фиксирует обнаруженные связи, а не назначает новые игровые соответствия.

## Правила миграции

- Ни один legacy ID не переименовывается и не удаляется на основании этой карты.
- Если утверждённый новый ресурсный ID не назначен, текущий ID сохраняется без преобразования.
- Нельзя заменять ID в инвентарях, экипировке, почте, квестовых JSON, коллекциях, активных очередях, аукционных лотах и истории простой глобальной подстановкой.
- Для активных заказов сохранять исходные `materials` и `output`; для лотов — item ID, владельца, резерв/статус и цену.
- Отсутствие ссылки в проверенных исходниках не доказывает отсутствие предмета в пользовательских данных.

- 11 статических legacy-рецептов используют старые материалы; их нельзя механически переписать на новые ID без утверждённых рецептур.
- 40 динамических рецептов легендарной брони используют `FLDROP-10-10-A`, `FLDROP-10-10-B`, `abyss_shard`, `relic_fragment`, `crystal_shard` и `ash_ore`.
- Runtime-операции заточки и мастерства комплектов используют `ash_ore`, `rune_shard`, `crystal_shard`, `abyss_shard`; идентификация — `rune_shard` и `crystal_shard`.
- `protection_seal` участвует в защите заточки и не заменяется ресурсом без решения.
- `faction_seal_dawn`, `faction_seal_caravan`, `faction_seal_lore` выдаются сюжетными цепочками и репутационными наградами.

## Безопасный следующий шаг

Сверить эту карту с полным утверждённым каталогом ресурсов и отдельно утвердить только однозначные пары «старый ID → новый ID». Все неоднозначные/неподходящие старые предметы остаются совместимыми без преобразования. Затем реализовать узкую миграцию с тестами для каждого хранилища. Рецепты четырёх металлических заготовок не реализовывать до утверждения точных расходов, выхода и времени: журнал сейчас фиксирует только принцип «один отдельный кузнечный рецепт непосредственно из соответствующего слитка».
